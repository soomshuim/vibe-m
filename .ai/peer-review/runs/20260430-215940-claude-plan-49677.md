Revised Plan: Wavvy Upload Finalization Harness v2

Scope:
- Add `python3 wavvy.py finalize-upload <series>` as the only command that performs final source archiving and optional txt deletion.
- Do NOT globally enforce this source contract in existing `validate` or `pack`; that would break older series. Instead, add a non-mutating opt-in check command/path used by finalize-upload.
- For current `SERIES/20-00`, restore deleted txt sources from git commit `b6f13c4^`, archive them into `concept.md`, then delete txt only after archive contract PASS.

CLI behavior:
- `finalize-upload <series> [--check] [--keep-txt] [--restore-from COMMITISH]`
  - `--check`: dry run; parse txt/report/concept and print planned archive/deletion, no writes.
  - `--keep-txt`: write concept archive but keep txt files.
  - `--restore-from b6f13c4^`: if txt files are missing, load deleted txt file content from that git tree for this command only, then materialize/rename as needed during real run.
- `validate` and `pack` remain backward compatible for all existing series. They may print a warning when no txt/Final Track Sources exists, but they must not fail because of the new harness.

Track source parsing:
- Required txt sections: `=== STYLE ===` and `=== LYRICS ===` only. LYRICS must be non-empty.
- `=== EXCLUDE ===` is optional. If absent, archive as `None`.
- Parse metadata fields when present: Track, Order, Type, BPM, Key, Length, Vocal.
- Preserve any extra tail section such as `=== META ===` or freeform post-lyrics metadata as `META` in the archive.

20-00 mapping:
- Never match restored txt to current WAV by old `Order:` because old Orders are stale (`Paycheck` was Order 04, now WAV 01).
- Match by title normalized case-insensitively, ignoring parenthetical suffixes and extra spaces. For `LLC (Low Light Code)`, normalize to `llc` and also accept the full title.
- Current WAV/report order is authoritative for final output order, filename, mood/genre/bpm, duration, sha256.
- Old txt `Order:` values are rewritten to current WAV order only in the archived concept block and in restored txt files if real run materializes them before deletion.

Concept archive format:
- Create/replace `## Final Track Sources` in `concept.md`.
- Each track includes: Timestamp, Repeat Timestamp if report repeat=2, Filename, Title, Mood, Genre, Type, BPM, Key, Length, Vocal, SHA-256, Source Title, Source Checksum, STYLE, EXCLUDE, LYRICS, META.
- Existing YouTube Metadata Track List remains the upload-facing list. Final Track Sources timestamps are archival/source timestamps; they must be calculated from the same `report.json` and checked against the first-pass upload-facing Track List where present, warning on mismatch.

Contract rules inside finalize-upload:
- report.json must exist and contain tracks matching current audio filenames/count.
- There must be exactly one source txt per report track, either from filesystem txt files or `--restore-from` git tree.
- Every source must have STYLE and non-empty LYRICS.
- Concept archive must contain exactly one complete Final Track Sources entry per report track before txt deletion.
- Only after archive verification passes may txt files be deleted, unless `--keep-txt` is set.
- Write concept through a temp file + replace to avoid partial writes. Recovery remains normal git checkout/reset of concept.md if needed.

Docs:
- `MASTER/WORKFLOWS.md`: staged SSOT transition: production txt SSOT; upload-final concept archive SSOT; txt deletion only via finalize-upload PASS.
- `MASTER/youtube/YOUTUBE.md`: Phase 2 final metadata requires running finalize-upload after package/report generation and before deleting txt.

Implementation notes:
- Prefer adding small dataclasses/helpers in `wavvy.py` near artifact generation/metadata parsing.
- Avoid adding package dependencies.
- Use existing logging functions.
- Keep older series behavior unchanged.
