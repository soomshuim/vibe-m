## 문제
Wavvy 전용 작사 스킬을 만들기 위해, 리서치 근거가 있는 스킬 명세와 실행 가능한 에이전트 하네스를 동시에 설계해야 한다.  
핵심 과제는 `품질 일관성(가사 결과물)`과 `재현 가능한 실행 경로(하네스 게이트)`를 함께 확보하는 것이다.

## 현재 상태
- 본 문서는 top-level play run 내부의 bounded artifact 작성 단계다.
- 세션 시작 필수 체크 결과:
  - Claude activity check 실행 완료 (2026-05-22 09:50:26 KST)
  - auto-handoff pending-clear: `action=none`, `clear_required=false`
- 저장소에는 기존 Wavvy 하네스/게이트 구조와 다수의 진행 중 변경사항이 존재하므로, 신규 스킬은 기존 SSOT/게이트 체계에 정합되게 붙여야 한다.
- 사용자 요청 문자열에 `-play`가 포함되어 있지만, 본 단계에서는 추가 러너 실행 없이 분석 산출물만 제공한다.

## 옵션
1. 경량 스킬 우선
- 리서치 최소화, 프롬프트 템플릿 중심으로 빠르게 스킬만 구성
- 장점: 초기 속도
- 단점: 품질 흔들림, 재현성/검증 약함

2. 하네스 우선
- 게이트/검증부터 만들고 스킬은 최소 기능으로 시작
- 장점: 운영 안정성
- 단점: 초기 창작 품질이 제한될 수 있음

3. 균형형(리서치+스킬+하네스 동시 설계)
- 작사 기준 리서치 → 스킬 계약(입력/출력/제약) → 하네스 게이트를 한 세트로 정의
- 장점: 품질과 재현성 동시 확보
- 단점: 초기 설계 비용 증가

## 권고안
옵션 3(균형형)을 권고한다.  
이유: Wavvy는 결과물 품질뿐 아니라 에이전트-친화적 운영(게이트, 상태, SSOT)이 중요하므로, 스킬 단독 제작보다 “근거 기반 규칙 + 검증 하네스”를 한 번에 맞추는 편이 총 비용이 낮다.

## 범위
- 포함:
  - 작사 리서치 범위 정의(장르/톤/금지 패턴/구조 규칙)
  - Wavvy 전용 작사 스킬 명세(입력 스키마, 출력 포맷, 실패 조건)
  - 에이전트 하네스 설계(초안 생성, 자기검수, 게이트 통과 기준)
  - 평가 지표(형식 준수, 훅 강도, 반복/진부성, 시리즈 컨셉 정합성)
- 제외:
  - 실제 오디오 생성/믹싱 자동화
  - 배포/업로드 단계 자동화 확장
  - 본 단계에서의 코드 직접 수정 및 러너 추가 실행

## 리스크
- 리서치 근거 부족 시 스킬이 취향 기반으로 드리프트할 수 있음
- 하네스 게이트가 과도하면 창의성이 저하될 수 있음
- 반대로 게이트가 약하면 품질 편차가 커짐
- 기존 미커밋 변경과 충돌할 경우 책임 경계가 불명확해질 수 있음
- (정책) 이미지/디자인 생성 요구가 추후 포함될 경우 경로 혼선 가능:
  - 일반 스케치/원오프 시각물: Codex `image_gen`
  - GPT Image 2/gen2 근거, 반복성, 배치, manifest/hash/request-id, 납품/클라이언트 리뷰 요구: OpenAI Images API `gpt-image-2`
  - 투명 PNG/알파 요구: `gpt-image-2` 기본 투명 배경 가정 금지, 후처리 게이트 별도 필요

## 게이트
- 분석 게이트:
  - 문제/현상/가정/범위가 문서에 명시되어야 함
- 스킬 게이트:
  - 입력/출력 계약, 금지 규칙, 실패 시 재시도 규칙이 명시되어야 함
- 하네스 게이트:
  - 최소 1회 자동 자기검수 루프와 판정 기준(PASS/FAIL/USER_DECISION) 필요
- 품질 게이트:
  - 포맷 준수 + 컨셉 정합 + 금지 패턴 미검출
- 운영 게이트:
  - SSOT/state 문서와 추적 가능한 변경 근거를 남길 수 있어야 함
